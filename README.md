# LabBank — S2 Ledger & Balance

Ledger and balance service built with ASP.NET Core, EF Core, and PostgreSQL.
This guide covers local setup and testing of the Session 4 ring endpoint by team S4.

## Prerequisites

- .NET SDK 10 and version 10 of the `dotnet-ef` tool.
- Docker Desktop running with support for Linux containers.
- Node.js and npm to run Redocly and Bruno through `npx.cmd` on Windows.

The commands below use PowerShell and run from the repository root unless stated otherwise.

## Database Setup

On the first run, if you do not already have a `.env` file:

```powershell
Copy-Item .env.example .env
```

Set `POSTGRES_USER`, `POSTGRES_PASSWORD`, and `POSTGRES_DB` in `.env`.
Use the same values for `Username`, `Password`, and `Database` in
`ConnectionStrings__Default`. When the backend runs on the host, the database
address is `localhost` on port `5433`; the internal container port is `5432`.
Do not commit `.env` or real connection credentials.

```powershell
docker compose up -d db
dotnet ef database update --project ".\src\Ledger_and_Inventory_Service\Ledger and Inventory Service.csproj"
```

If the project database already exists in the volume, use its existing
credentials. Changing `.env` variables alone does not update the user or
password of an existing database.

## Running the Service and Seeding Demo Data

To create demo data, run the service with the following option:

```powershell
dotnet run --project ".\src\Ledger_and_Inventory_Service\Ledger and Inventory Service.csproj" --launch-profile http -- --SeedDemo=true
```

Seeding is only allowed in `Development`. It creates two demo accounts and
three balanced journal entries through `PostingService` in one transaction.
After a successful run, running it again does not create duplicate data.
Seeding fails if the demo account IDs are already in use or only some of
the demo journal entries exist.

| Account | ID | Balance After Seeding |
| --- | --- | ---: |
| A, source | `0192a7d0-0000-7000-8000-000000000001` | 750,000 IRR |
| B, destination | `0192a7d0-0000-7000-8000-000000000002` | 250,000 IRR |

Account A receives an opening balance of 1,000,000 IRR, followed by two
transfers of 100,000 and 150,000 IRR to B. Journal timestamps reflect the
actual seed execution time. These demo entries have not been reversed,
so their `is_reversed` values are `false`.

For subsequent runs without requesting seeding:

```powershell
dotnet run --project ".\src\Ledger_and_Inventory_Service\Ledger and Inventory Service.csproj" --launch-profile http
```

Keep the service terminal open and run the following requests in a second terminal.

## Available Endpoints for Ring Testing

| Route | Purpose |
| --- | --- |
| `GET /health` | Service liveness |
| `GET /ready` | Database connectivity check |
| `GET /api/v1/accounts/{id}/entries` | Read account journal lines from PostgreSQL for S4 |

Other routes listed in OpenAPI are not necessarily fully implemented.
This list alone does not satisfy the assignment requirement for two endpoints
that access business data in the database.

```powershell
curl.exe -i "http://localhost:8082/ready"
curl.exe -i "http://localhost:8082/api/v1/accounts/0192a7d0-0000-7000-8000-000000000001/entries?direction=DEBIT&limit=50"
```

After seeding and before modifying the demo data, the second request returns
`200` with two debit items, with amounts of 150,000 and 100,000 IRR, in that order.

### Parameters and Reversal State

- `direction`: optional; `DEBIT` or `CREDIT`. Both directions are returned when omitted.
- `from`: optional ISO 8601 UTC timestamp with a `Z` suffix; the lower bound is inclusive.
- `limit`: defaults to 50; minimum 1, maximum 200. This is a per-page limit.
- `cursor`: the previous page's `next_cursor`; the account, direction, and `from` filters must remain unchanged.
- `X-Correlation-ID`: accepted or generated by the service and returned in the response header.

Each item represents one journal line belonging to the account. Results are
ordered by `posted_at`, `entry_number`, and `line_no`, all descending. To read
all results, follow pages until `next_cursor` is `null`. No snapshot across
pages is guaranteed.

The required `is_reversed` field is derived from the existence of a reversal
entry for the item's journal entry, even when the reversing line is excluded
by the direction filter. It reflects the current state, not a historical
as-of state. An item with `entry_type: REVERSAL` does not automatically have
`is_reversed: true`. This endpoint does not apply S4's daily-count policy.

### Pagination

```powershell
$entriesUrl = "http://localhost:8082/api/v1/accounts/0192a7d0-0000-7000-8000-000000000001/entries"
$page1 = Invoke-RestMethod "${entriesUrl}?limit=1"
$page1 | ConvertTo-Json -Depth 10
if ($null -ne $page1.next_cursor) {
    $entriesCursor = [uri]::EscapeDataString($page1.next_cursor)
    $page2 = Invoke-RestMethod "${entriesUrl}?limit=1&cursor=${entriesCursor}"
    $page2 | ConvertTo-Json -Depth 10
}
```

### Errors

```powershell
curl.exe -i "http://localhost:8082/api/v1/accounts/not-a-uuid/entries"
curl.exe -i "http://localhost:8082/api/v1/accounts/0192a7d0-0000-7000-8000-000000000001/entries?limit=0"
curl.exe -i "http://localhost:8082/api/v1/accounts/ffffffff-ffff-ffff-ffff-ffffffffffff/entries"
```

The first two requests return `400 ERROR_VALIDATION`. The third returns
`404 NOT_FOUND` if the account does not exist. An existing account with no
matching journal lines returns `200` with `items: []`. Errors use
`application/problem+json`.

## OpenAPI Contract and Swagger UI

The source of truth for the contract is `openapi/ledger.yaml`. The copy under
`src/.../OpenApi` is retained for compatibility with the previous structure
and must stay synchronized when the contract changes.

```powershell
npx.cmd --yes @redocly/cli lint openapi/ledger.yaml
```

To create the Swagger UI container for the first time, run from the repository root:

```powershell
docker run -d --name swagger --restart unless-stopped -p 8088:8080 -v "${PWD}/openapi:/spec:ro" -e SWAGGER_JSON=/spec/ledger.yaml swaggerapi/swagger-ui
```

If the container already exists, use `docker start swagger` instead of creating
it again. Open `http://localhost:8088` to view the contract; refresh the page
after YAML changes. The backend runs at `http://localhost:8082`, and the
Development CORS policy allows the Swagger UI origin.

For the report, capture one actual `200` response and one error response from
`Try it out` on the ring endpoint. Include the request URL, status code, and
a readable response body.

## Running Bruno Requests

After seeding, with the backend and database running:

```powershell
Push-Location ".\bruno\ledger"
npx.cmd --yes @usebruno/cli run
Pop-Location
```

The collection covers successful debit retrieval, invalid input, and a missing
account. The success test also checks the boolean `is_reversed` field and
that the supplied correlation ID is returned.

## Running .NET Tests

```powershell
dotnet test ".\tests\Ledger.Tests\Ledger.Tests.csproj"
```

Docker must be running. Integration tests create temporary PostgreSQL instances
using Testcontainers and do not use the project's local database. The reversal
test checks both debit and credit cases before and after posting a reversal.
